# Релиз 0.5.36 — агрегированная аналитика журнала и регистраций

Дата: 19 ноября 2026. Базовый релиз: 0.5.35 (и hotfix публикации №96). Часть 90-дневной стратегии: `STAZHNO_STRATEGY_90_DAYS.md`.

## Цель

Проверить гипотезу **полезные статьи → переход к вакансии/профилю**, не создавая профили поведения и не связывая анонимное чтение с зарегистрированными пользователями.

## Что измеряется

- `view`: количество загрузок страниц журнала, при которых выполняется JS (не уникальные посетители).
- `jobs_click`: клик по размеченному переходу к поиску вакансий.
- `profile_click`: клик по размеченному переходу к созданию профиля.
- Отдельно из текущей таблицы `users`: новые кандидаты и работодатели за период.

Группировка: **день по UTC, одна из четырёх допустимых страниц, один из трёх видов действия, количество**. Четыре колонки в таблице `growth_daily_counts`: `event_date`, `source`, `action`, `total`. Строки со старыми днями удаляются при поступлении новых событий, с целевым хранением 180 дней; при полном отсутствии трафика очистка откладывается до следующего события.

**Не собираем:** email, ФИО, телефон, IP-адрес, User-Agent, cookie, идентификатор сессии/устройства, UTM/реферер, содержимое резюме, данные работодателя и сырой журнал событий. Браузерная отправка использует `credentials: 'omit'` и `referrerPolicy: 'no-referrer'`; событие содержит только `source` и `action`. Аналитика не препятствует просмотру статей и переходам, если сеть недоступна.

Публичный журнал показывает уведомление о подсчёте суммарных событий. Страницы с крупным шрифтом сохраняют работу. Отдельный маркетинговый профайлинг и рекламные системы не внедряются.

## Доступ и безопасность

- `POST /api/growth/event`: принимает только строго определённые значения; прочие отклоняются с 422. Действующие CSRF/origin и ограничение размера запроса остаются.
- `GET /api/admin/growth?days=30`: только администратору с действительной сессией и MFA; выбор диапазона 1–90 дней. Возвращает исключительно суммы.
- Новая таблица создаётся **идемпотентно** при старте для существующих SQLite и PostgreSQL; старые таблицы не меняются, миграция персональных данных не требуется.
- Административная панель выводит общие показатели и таблицу по страницам; не добавляются ни публичные метрики, ни списки людей.

## Как интерпретировать правильно

Это **не сквозная воронка на уровне пользователей**: переход в профиль не означает регистрацию, а число регистраций не привязано к конкретной статье. Суммы могут включать несколько загрузок страницы одним человеком; часть событий теряется из-за браузерных ограничений, блокировки JavaScript и сети, а технический трафик может завышать значения.

Для следующего этапа исследования нужны интервью, результаты откликов, качественные проверки вакансий и отдельно подтверждённые собеседования. Не публиковать «конверсию в регистрацию из статьи» на основании этих агрегатов.

## Приёмка

1. Python/API: только допустимые события; нет необработанных идентификаторов и накопления событий по одному пользователю.
2. API: 401 без авторизации, 403 не-администратору, корректные суммы зарегистрированных кандидатов и работодателей.
3. SQLite и реальный PostgreSQL: upsert работает атомарно, схема создаётся повторно без ошибок.
4. Browser smoke, мобильные сценарии, журнал и крупный шрифт — работают.
5. CodeQL и другие security-checks — зелёные.
6. После merge подтверждены новый `main` и Timeweb, включая проверку точных HTML страниц журнала. В отличие от общего журнала, доступность приватного admin API не должна утекать анонимному проверяющему.

## Следующий этап: не только код

Использовать задачу [Growth-пилот №95](https://github.com/Arromanov1985/opyt50-platform/issues/95): 20 интервью с кандидатами, 10 с работодателями, запуск личных приглашений и тестирование двух первых профессиональных сегментов. Вопрос о профессиональных рекомендациях решать после исследования спроса и модели модерации.

> Перед масштабным внешним продвижением нужно провести юридическую проверку публичных уведомлений и обработки персональных данных на основных доменах и подключить рабочий основной домен. Публикация этого релиза **не выполняет** смену DNS и не запускает рекламную кампанию.
