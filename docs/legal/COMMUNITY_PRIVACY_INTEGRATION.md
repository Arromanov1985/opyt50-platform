# Взаимодействие запроса на прекращение обработки с профессиональным сообществом

**Статус: техническая подготовка в черновике PR #99.** Публичный запуск заблокирован issue #98; текст не заменяет юридическое заключение.

После добавления сообщества в PR #107/108 старые ограничения из `privacy_restriction.py` покрывали только вакансии и отклики. Этот блок синхронизации добавляет независимые проверки нового модуля:

- Публичный каталог `/api/community/people`, HTML `/people/{public_id}`, API профиля и статус опубликованного участника исключают активные заявления `deletion` и `stop_processing` со статусами `received`, `in_review`, `completed`.
- Собственные новые изменения профиля, новая публикация, новые профессиональные знакомства, согласия и отправка сообщений ограничиваются с 409 (авторизованный пользователь). Входящее сообщение и принятие знакомства блокируются для участника с активным ограничением. Публичные URL возвращают 404 без раскрытия причин скрытия.
- Владелец сохраняет доступ к собственной истории, экспорту и обращениям; может снять публикацию, отменить запрос на контакт, заблокировать собеседника и подать жалобу. Ни одного автоматического `DELETE` по реальным таблицам пользователей и переписок нет.
- При отклонённом обращении технический фильтр перестаёт скрывать профиль, если нет других ограничений. Ранее вручную отозванная публикация не возвращается автоматически.
- Интеграционный тест `test_privacy_request_hides_public_community_profile_and_stops_new_actions` использует только вымышленных пользователей и изолированную БД; должен проходить вместе с существующими тестами сообщества, прав и PostgreSQL.

**Важные юридические пределы:** техническое скрытие не удаляет исторические сообщения, ранее предоставленные контакты, журналы хостинга, резервные копии и данные получателей. Не доказывает исполнение обращения. Для таких действий в PR #99 есть ручная матрица `ERASURE_AND_CESSATION_PLAN.md` и `RETENTION_AND_PROVIDER_RUNBOOK.md`. Требуются реальные сроки, проверенные правовые основания и решения уполномоченного оператора.

Новые функции сообщества не должны публиковаться вместе с тестовыми реквизитами «ИП Иванов Иван Иванович». Не менять `TEST_ONLY` или `Legal readiness (technical)` ради успешной публикации.
