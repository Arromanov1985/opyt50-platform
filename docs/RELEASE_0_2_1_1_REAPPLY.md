# ОПЫТНО.РФ — 0.2.1.1: Повторный отклик и наблюдаемость

## Проблема, обнаруженная при ручной приёмке
В тестовой очереди зафиксировано событие `new_application`, а через несколько секунд — `application_withdrawn`. В первоначальном MVP стоял уникальный индекс (вакансия, кандидат): повторный отклик после отзыва возвращал HTTP 409. При этом в админпанели были счётчики приглашений, но не было числа откликов, поэтому создавалось впечатление, что действие не дошло до работодателя.

## Исправления
1. Если заявка отозвана, кандидат вправе подать её повторно на **ту же открытую вакансию**. Сохраняется прежний ID заявки — не появляется дубликат и не нарушается уникальность пары кандидат/вакансия.
2. Каждое новое действие записывается в `application_events`: `applied`, `withdrawn`, `reapplied`, а также статусы работодателя (`reviewing`, `interview`, `rejected`, `hired`). Старые события из предыдущих версий не реконструируются задним числом.
3. «Мои отклики» показывает хронологию для новых действий и кнопку «Откликнуться повторно» только при статусе `withdrawn`. Отклонённые и завершённые заявки нельзя подать повторно по этому маршруту.
4. Счётчики администратора: «Всего откликов» (уникальные пары), «Активные отклики» (отправлен, на рассмотрении, заинтересован), «Отозванные отклики». **Отклик не равен приглашению**, поэтому их показатели должны отличаться.
5. При повторной подаче отправляется новое событие только в демо-очередь. Настоящая почта отключена.
6. Тесты API и браузера проверяют отзыв → повторную подачу → сохранение ID, отсутствие дублей, сохранение истории, отображение счётчиков и дальнейшую работу сценария знакомства.

## Ограничения
- Работодатель всё равно видит только обезличенный профиль до отдельного согласия на передачу контактов и демонстрационного знакомства.
- Временная тестовая SQLite-база; никаких реальных анкет и платежей.
- Это **новая ветка** `feature/release-0.2-application-retry`, а не `main` и не используемая Timeweb ветка `feature/release-0.2-unified-introductions`. Текущий стенд не меняется без согласованного переключения.

## Сценарий приёмки
1. В аккаунте `buhgalter@demo.example` открой «Мои отклики» и найди «Бухгалтер».
2. Если отклик отозван, после запуска этой версии нажми «Откликнуться повторно». Если ещё активен, этот шаг не нужен.
3. В кабинете работодателя открой «Отклики соискателей», нажми «Заинтересован · запросить согласие».
4. Кандидат должен увидеть запрос рядом со своим откликом, открыть приглашение и отдельно разрешить передачу контактов.
5. Работодатель выполняет только демо-подтверждение знакомства; повторного приглашения не создаётся.
6. Администратор видит отдельно отклики и приглашения.
