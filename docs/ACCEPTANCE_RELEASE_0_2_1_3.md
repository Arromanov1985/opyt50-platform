# ОПЫТНО.РФ — протокол приёмки 0.2.1.3

Дата ручной приёмки: 08.10.2026.
Стенд: существующий Timeweb Cloud App Platform `opytno-preview`, домен предварительного просмотра `arromanov1985-opyt50-platform-fdd8.twc1.net`.
Код зафиксированной версии: ветка `feature/release-0.2-application-state` (база последующих исправлений). Версия интерфейса и /api/health: `0.2.1.3`.

## Решение
**Основной демонстрационный сценарий знакомства принят** по предоставленным в ходе ручной проверки скриншотам; это **не** означает завершение полной приёмки всех функций или готовность к работе с реальными данными.

Подтверждено: Наталья (вымышленный соискатель) видит рекомендованную профильную вакансию «Бухгалтер», отправляет отклик, статус отражается в личном кабинете и у работодателя. Компания «Пример» выражает заинтересованность из отклика; создаётся запрос согласия. Кандидат принимает его с отдельным согласием; работодатель видит «Согласие получено». После подтверждения демонстрационной операции за 2 990 ₽ открываются **только вымышленные** имя, email и телефон. В рабочем режиме оплата отключена; реальные средства не списываются.

Не подтверждено только скриншотами: отсутствие дублей в БД при повторном нажатии, все пограничные переходы статусов, ограничения доступа к чужим откликам, доставка внешних email, реальные платежи, устойчивое хранение SQLite при пересоздании контейнера. Соответствующие инженерные проверки — отдельные тесты.

## Замечания, вынесенные в отдельную ветку
1. После открытия контакта разные экраны продолжают показывать промежуточное состояние «Работодатель заинтересован», вместо итогового «Знакомство состоялось (демо)».
2. После получения согласия/открытия контакта работодателю доступны нелогичные действия «Рассмотреть»/«Отказать»; это нужно заблокировать **и на сервере**, и в интерфейсе.
3. История отклика, приглашения, согласия и демонстрационного открытия контакта разделена между экранами, требуется единая временная шкала.
4. Перед объединением в `main` требуется расширенная автоматизированная регрессия: избранное, фильтры, повторные отклики, админ-права, разграничение доступа, согласие, отсутствие повторного демо-списания и мобильное представление.

## Порядок выпуска
Этот документ входит в ветку `feature/release-0.2-interaction-finalization`, созданную **от** проверенной `feature/release-0.2-application-state`. Работающий Timeweb и `main` не меняются. Merge только после зеленых тестов, отдельной ручной приёмки новой версии и согласования. До отдельного согласия не подключать реальные письма, платежи, внешние платные службы или персональные данные.
