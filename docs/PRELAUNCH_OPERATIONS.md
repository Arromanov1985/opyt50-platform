## 1. Публичная диагностика без секретов

GitHub Actions → STAZHNO public infrastructure diagnostics. Workflow проверяет
публичные записи A/AAAA/MX/SPF/DMARC, HTTPS с проверкой сертификата и JSON health
для stazhno.ru и технического домена. Сохраняет только статусы, не IP-адреса,
полные DNS-ответы, содержимое писем, учётные данные или исключения.
Зелёный workflow означает выполнение диагностики; изучить каждое поле отчёта.
Отсутствие AAAA само по себе не препятствует запуску. Наличие MX/SPF/DMARC не
означает корректность политики или доставки. DKIM проверить по фактическому
селектору, указанному почтовым провайдером, и заголовкам тестового письма.
Не менять DNS по одному результату проверки, не включать регистрацию.

## 2. Одна ручная проверка в панели Timeweb

Открыть используемую управляемую PostgreSQL БД: зафиксировать только
фактический регион, включённость резервирования, время последней успешной
копии, срок хранения и доступность восстановления. Сверить, что приложение
подключено именно к этой БД. Не копировать пароли, DSN, IP, имена
ресурсов, содержимое базы или снимки в публичный GitHub/чат.
Восстановление проводить только в отдельно согласованную изолированную
среду, не поверх production; если требуется новый платный ресурс, сначала
согласовать стоимость. Не повторять миграцию SQLite.

Проверить параметры безопасности приложения по scripts/security_preflight.py
в доверенном runtime или панели: production, HTTPS, secure cookie, MFA,
запрет demo seed, доступ к техническому стенду, TLS БД, SMTP TLS.
Отдельно убедиться в фактическом подключении БД и выполнении восстановления:
preflight конфигурации не заменяет эти проверки.

## 3. Почта

До юридического допуска не создавать новые реальные аккаунты. Использовать
существующий отдельно разрешённый синтетический аккаунт с подконтрольным
тестовым ящиком. Не запускать массовые рассылки, не запрашивать письма на
реальные адреса пользователей. Проверить получение верификации и сброса,
срок действия/одноразовость ссылок и заголовки Authentication-Results
(SPF/DKIM/DMARC). Не пересылать ссылки, коды, пароли или полный исходник писем.
Зафиксировать время и результат получения, включая папку спама.
