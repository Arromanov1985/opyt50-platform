# ОПЫТНО.РФ: уведомления об изменении условий вакансий (итерация 0.3)

## Цель
Уже откликнувшийся кандидат должен узнать, что работодатель поменял условия вакансии. Уведомление доступно только в его личном кабинете. Никакие реальные email/SMS, внешние сервисы или оплаты не подключаются.

## Сценарий
1. Работодатель открывает «Мои вакансии» → «Редактировать», меняет зарплату, описание или другие условия, проверяет предпросмотр и сохраняет.
2. `PATCH /api/employer/vacancies/{id}` обновляет ту же вакансию (без нового ID), а внутри той же транзакции создаёт запись об изменении, включая предыдущее и новое значение каждого действительно изменённого поля.
3. Система фиксирует список получателей **на момент сохранения**: соискатели с неотозванными откликами на вакансию и получившие активное приглашение (`sent`/`accepted`), без дублей. Появившиеся позднее кандидаты не получают старые сообщения.
4. В личном кабинете соискателя доступен раздел **«Изменения условий»**. Для каждого изменения показаны вакансия, компания, дата и значения «Было / Стало».
5. В «Моих откликах» появляется уведомление о непрочитанных изменениях. Соискатель может открыть список и явно нажать **«Отметить прочитанным»**. Прочитанное остаётся в истории, счётчик непрочитанных уменьшается.
6. Кандидат видит только адресованные ему изменения. Роль работодателя получает HTTP 403, попытка отметить чужое изменение прочитанным — HTTP 404.
7. Если содержимое вакансии фактически не меняется, запись не создаётся; отказанный из-за `expected_revision` запрос HTTP 409 также ничего не создаёт.
8. Отозвавший отклик соискатель не получает новые изменения только на основании этого отклика. Отдельное ранее принятое приглашение может сохранять основание для уведомления.
9. Сохранение изменения не снимает согласия на передачу контактов, не меняет статус отклика и не открывает новые контакты. Изменения условий **не сопровождаются автоматическим согласием** соискателя. Будущая задача — отдельная политика на случай существенных изменений условий после открытия контакта.
10. Хранение: таблицы `vacancy_updates` и `vacancy_update_recipients` добавляются идемпотентной миграцией при запуске. Старые вакансии, приглашения и отклики остаются неизменными.

## Не входит в задачу
Email/SMS/push, реальная рассылка, обработка персональных данных, монетизация, платёжный сервис, изменение согласий и миграция в промышленную БД.

## Критерии приёмки
- Показать объявление до и после изменения зарплаты.
- Убедиться, что соискатель, ранее откликнувшийся на объявление, видит его изменения в личном кабинете.
- «Было / Стало» соответствует сохранённым условиям; интерфейс не допускает HTML-инъекций и не переполняет мобильную ширину 390px.
- Нажатие «Отметить прочитанным» уменьшает счётчик, но не стирает историю.
- Другой соискатель, откликнувшийся после изменения, не видит чужую прежнюю историю.
- Системные тесты: права доступа, отказ от уведомления при отозванном отклике, HTTP 409, прежние отклики, приглашения и согласия, отсутствие внешней почты.
- Ручная проверка на Timeweb **только после отдельного согласия пользователя**.
