Базовый функционал Академии закрыт релизом #172, SHA 591de4ed.
Это контроль технического стенда, а не разрешение на публичный запуск.

## 1. Автоматические доказательства

Для точного финального SHA основной ветки:
- Python/API и все браузерные сценарии; CodeQL; PostgreSQL на том же SHA;
- Verify published STAZHNO release: файлы, HTML, manifest, sitemap,
  защищённые API кабинетов и сообщества, валидный JSON health;
- до юридического утверждения: серверные признаки закрытой регистрации,
  noindex/nofollow и no-store на главной; после утверждения — наблюдаемое
  состояние опубликованного сайта, а не только отметка в checkout.
  Оба режима требуют совпадения контрольной суммы версии юридических
  файлов (оператор, согласование, реестр хранения, три шаблона и код
  конфигурации). Docker содержит согласование и реестр. Запрет POST
  регистрации проверяется в изолированном production-mode CI;
  совпадение файлов не подтверждает юридическую действительность;
- автоматическая проверка никогда не вводит реальные данные на Timeweb,
  не пытается входить в кабинеты и не отправляет POST-запросы;
- кодекс-ревью финального PR и отсутствие неустранённых замечаний.

Публикация на техническом домене не означает открытие публичной регистрации.
Не подтверждать релиз по одному HTTP 200 или отсутствию ошибок в браузере.

## 2. Единый ручной проход перед запуском

| Сценарий | Что должно быть проверено |
| --- | --- |
| Кандидат | Профиль, поиск, отклик, согласие, отказ, история, выход |
| Работодатель | Вакансия, воронка, приглашение, взаимное согласие, завершение знакомства |
| Приватность | Чужие данные недоступны, контакты только после согласия, жалоба/запрос, отзыв |
| Сообщество | Профиль по согласию, модерация, блокировка и сообщения |
| Академия | Черновик редакции, предпросмотр, публикация после подтверждения, программа, отзыв |
| Мобильность | 360/390/768/1280 px, крупный текст, клавиатура, ошибки и пустые состояния |
| Почта | Верификация и восстановление на разрешённых тестовых адресах; CI не доказывает доставку |
| Эксплуатация | Актуальные внешние резервные копии, восстановление в изолированной БД, мониторинг, MFA администратора |

На техническом стенде не использовать реальные анкеты и новые реальные
регистрации. Ролевые сценарии автоматизированы в изолированных БД; ручной
проход на стенде только с разрешёнными тестовыми аккаунтами.
Не повторять миграцию SQLite, не очищать PostgreSQL, не менять сеть или
платные ресурсы: исторический cutover уже выполнен, актуальные состояние
резервирования и восстановление нужно подтвердить отдельно.
