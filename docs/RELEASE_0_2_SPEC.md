# ТЗ: ОПЫТНО.РФ — Релиз 0.2 «Полноценный поиск работы»

Статус: разработка в отдельной ветке. Исходный MVP 0.1 сохраняется. На Timeweb ветка main не изменяется до проверок и согласования релиза.

## Цель
Кандидат самостоятельно ищет, фильтрует, сохраняет вакансии, откликается и отслеживает решения. Работодатель получает заявки без раскрытия личных контактов до отдельного согласия и демо-знакомства. Владелец управляет статусами, получает автоматические события и контролирует сервис без рекрутеров.

## Роли и сценарии
- Гость: поиск по названию, городу, зарплате от и графику; карточка с должностью, компанией, зарплатным диапазоном, графиком, занятостью, навыками и описанием. Отклик/избранное только после входа.
- Кандидат: сохранение/удаление вакансии в избранном, отклик на открытую вакансию (один активный отклик на вакансию); просмотр истории, статуса и даты; возможность отозвать отклик. Отклик не равен согласию на публикацию контактов.
- Работодатель: просмотр обезличенных откликов только по своим вакансиям, смена статуса заявки, действующий механизм приглашения/демо-знакомства без обхода согласия.
- Администратор: перечень пользователей, временная блокировка/разблокировка обычных аккаунтов, перечень вакансий, открытие/закрытие вакансий с журналом действий; без прав на просмотр паролей/токенов.
- Почта: события регистрации, отклика, изменения статуса и приглашения попадают в тестовую очередь; **реальные письма не отправляются** без согласования SMTP/почтового провайдера. Срок действия одноразовых токенов верификации/сброса, хранение только хешей токенов, сброс завершает действующие сессии.
- Email-verification: незавершённое подтверждение отображается в кабинете; на MVP верификация не блокирует вход, пока нет подтверждённого работающего почтового канала.
- Избранное: уникальность пары кандидат/вакансия, перечень в кабинете; статус закрытой вакансии сохраняется.
- Модерация: право блокировать пользователя, скрывать вакансию, защита от самоблокировки администратора.

## Ограничения безопасности
- Подтверждение email не является согласием на передачу телефона/почты работодателю.
- Соискатель не платит; эквайринг не подключается.
- SQLite остаётся **только для тестового стенда**; перед реальными пользователями: PostgreSQL, бэкапы, удаление/отзыв согласий, оператор ПД, DPA, аудит, лимиты запросов и юридическая проверка.
- Тестовый стенд защищён Basic Auth; никаких реальных анкет, реквизитов SMTP или персональных данных.
- Профили и контакты пользователей не выводятся в ответах публичного поиска и списка откликов работодателя.
- Фильтры не применяют возрастных критериев.
- Переменные и секреты хранятся только в настройках Timeweb, не в публичном GitHub.

## Критерии приёмки
1. Гость фильтрует вакансии по 4 признакам и получает только открытые вакансии, с безопасным ограничением числа результатов.
2. Кандидат может добавить/удалить избранное, дважды добавить нельзя; видит сохранённые вакансии.
3. Кандидат отправляет отклик только на открытую вакансию, повторный отклик блокируется; работодатель видит только свою заявку без ФИО/email/телефона.
4. Статус меняет только владелец вакансии; кандидат видит его в истории и может отозвать активный отклик.
5. Регистрация/отклик/приглашение/смена статуса создают записи в тестовой очереди уведомлений. Нет сетевой отправки.
6. Token-based email confirmation и password reset имеют TTL, однократное использование, не раскрывают существование email в публичном ответе, сброс инвалидирует сессии.
7. Админ может блокировать кандидата/работодателя и закрыть вакансию, но не может блокировать самого себя.
8. Все сценарии релиза 0.1 и демо-платежи не сломаны. Проверены автоматическими тестами.
9. Сайт сохраняет брендбук: #083664, #007FCE, #00C7B8; используется текущая адаптивная версия.
