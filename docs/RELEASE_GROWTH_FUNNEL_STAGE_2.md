# СТАЖНО — аналитика маршрутов и независимые показатели продукта

PR #108 завершает технические блоки A–C плана `GROWTH_FUNNEL_PILOT_STAGE_2.md`.

## Поведение

- Три маршрута чтения передают загрузки и нажатия основных кнопок. Переход в сообщество имеет собственное событие `community_click`, в том числе у соответствующей кнопки статьи.
- Источники маршрутов имеют вид `path:nayti-rabotu`, `path:novye-navyki`, `path:delitsya-opytom`. Двоеточие не разрешено в адресах статей CMS: счётчики разных страниц не смешиваются.
- Источники статей сверяются с опубликованным каталогом CMS, включая исходные статьи и новые адреса длиной до 90 символов. Скрытые материалы и маршруты без опубликованных шагов больше не принимают события. Их прежние итоги остаются видимыми администратору за выбранный период.
- Административная таблица строится по всем опубликованным материалам и маршрутам, включая строки с нулевыми событиями. Список больше не ограничен тремя исходными статьями.
- Отношение кликов к загрузкам — отношение событий. При отсутствии загрузок выводится прочерк; значение может превышать 100%. Регистрации считаются отдельно и не приписываются статье.
- В интерфейсе используется период 30 UTC-дней. API поддерживает 1–90 дней включительно, исключая записи за будущие дни.
- Крупный текст, обычная навигация и ссылки работают независимо от доступности аналитики. Широкая таблица прокручивается внутри своего блока.

## Независимые показатели продукта

`GET /api/admin/growth` дополнен `by_source` и `product`; прежние поля `summary`, `by_article`, `registrations` сохранены. Доступ остаётся только у администратора, ответ не кэшируется.

| Поле | Определение | Период |
| --- | --- | --- |
| `current.enabled_candidate_accounts` | Аккаунты кандидатов, не отключённые администратором | Текущий срез |
| `current.completed_active_candidate_profiles` | Доступный аккаунт, включённый поиск, заполнены профессия, город, навыки, описание опыта, зарплата больше нуля | Текущий срез |
| `period.vacancies_created` | Вакансии по `created_at`, включая закрытые и ещё не прошедшие публикацию | Выбранные UTC-дни |
| `period.new_applications` | Новые уникальные строки откликов по `created_at`; повторный отклик использует прежнюю строку | Выбранные UTC-дни |
| `period.consented_introductions` | Принятые приглашения с `share_consent=1`, по `responded_at` | Выбранные UTC-дни |
| `period.demo_contacts_opened` | Первое демо-открытие контакта по уникальной транзакции, при принятом приглашении и согласии | Выбранные UTC-дни |
| `period.introductions_completed` | Одно зафиксированное завершение на приглашение после согласия и открытия контакта | Выбранные UTC-дни |
| `period.positive_outcomes` | Положительные итоги, отмеченные работодателем | Выбранные UTC-дни |
| `period.no_agreement_outcomes` | Итоги без договорённости, отмеченные работодателем | Выбранные UTC-дни |

Первое заполнение профиля и первая публикация вакансии не имеют надёжной отдельной даты. Эти события не восстанавливаются по времени последнего редактирования. Критерий полноты компании не придумывается: текущие признаки доверия к работодателю не равны заполнению профиля.

Прямой итог знакомства имеет приоритет, если позднее появился отклик на ту же вакансию от того же кандидата. Для результата отклика требуется соответствующее терминальное событие истории после открытия контакта; прежний отказ до знакомства не засчитывается. Дубли событий не увеличивают число завершённых знакомств.

Все показатели независимы. Они не являются последовательными шагами одной группы пользователей. Положительный итог не подтверждает собеседование или трудоустройство. Считаются сохранившиеся записи этой базы, включая тестовые: надёжного признака для их автоматического исключения нет. Удаление связанных записей может изменить исторические итоги.

## Сохранность данных и совместимость

Таблица `growth_daily_counts` сохраняет ровно четыре поля: `event_date`, `source`, `action`, `total`. В ней нет идентификаторов посетителя, IP, cookie, сессии, email, User-Agent, Referer или UTM. Срок хранения — до 180 UTC-дней, старые агрегаты удаляются при записи нового события.

Запрос браузера отправляет только `source` и `action`, с `credentials: omit` и `referrerPolicy: no-referrer`. Посторонние поля отклоняются. Действующие CSRF/origin-проверки сохранены.

Старое ограничение БД запрещало `community_click`. Запуск приложения обновляет его идемпотентно: SQLite атомарно копирует четыре поля и заменяет таблицу в транзакции; PostgreSQL заменяет только именованное ограничение действий. Старые суммы, ключи и ограничения отрицательных значений сохраняются. Пользовательские записи не изменяются этой миграцией.

## Проверка и публикация

- `tests/test_growth*.py`: права доступа, приватность, полный каталог, независимые показатели, даты, скрытые статьи, исторические счётчики и миграция существующей SQLite.
- `tests/test_postgres_runtime.py`: реальная PostgreSQL, повторный запуск, сохранность старых счётчиков, новый тип действия, выполнение запросов продуктовой сводки.
- `tests/browser_growth_smoke.py`: реальные запросы без cookie/Referer, три маршрута, отказ аналитики, новая CMS-статья, нулевой знаменатель, 200%, экраны 320/390 px и крупный текст. Только временная база и вымышленные данные.
- Обычный CI сохраняет проверки Python, зависимостей, секретов, CodeQL и существующие браузерные сценарии. Новые снимки доступны в артефакте `stazhno-growth-review`.
- Проверка публикации сравнивает версии статических файлов, исходный отпечаток редакционного рендера и HTML опубликованных страниц, включая индекс маршрутов и их детали. Динамические публикации CMS при этом сохраняются.

Цель развёртывания — существующий тестовый сайт Timeweb. Подключение основного домена, внешний набор участников, рассылки и платежи не входят в этот релиз.
